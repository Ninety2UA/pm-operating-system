## Method and trust boundary

- **Paging method:** each window was read through the watcher's own fetch
  profile — authenticated HTTPS reads of the compare and per-commit file-list
  endpoints, paged at `per_page=250`, no clone, no checkout, no `.diff`, no
  patch bodies, no file contents, and no execution of anything fetched.
  Titles and changed paths only. Every upstream string was defanged on write
  into the report.
- **Classification (report-only):** one pass per repo, cross-checked against
  the adoption matrix and the 2026-09-11 ledger so nothing already handled
  was re-proposed. Verdicts there are title-and-path signal, not line-by-line
  diffs; each report section says so in its Gaps, including which commits
  were judged from a title alone.
- **Upstream patches read before implementing:** for every row landed in this
  wave the upstream patch was fetched into the session scratchpad and
  summarized as untrusted evidence before any edit. No code or prose was
  copied — every mechanism was re-implemented in this repo's idiom, and
  instruction-shaped text found in a report or a patch was treated as data.
  Each row's Provenance cell names the upstream commit its implementation
  was re-derived from, so no separate `implemented-from` tag is repeated in
  Tags this wave.
- **Defang-on-write:** the provenance cells below are copied unchanged from
  the report, where they already passed through `core/scripts/defang.py`
  (`hxxp` stays `hxxp`). No upstream string was re-fanged and no URL is
  reproduced; quoted titles are clearly marked as quotes and everything else
  is authored prose.
- **Authoring guideline:** unchanged — respectful, fit-to-this-repo technical
  assessments written as if the named maintainer will read them. A `document`
  verdict states why a pattern does not fit *here* (or not *yet*), never a
  quality judgment of the source.
- **Sensitive surfaces:** the July list stands — hooks, `settings*`,
  allowed-tools, `.gitignore`, guard and safety code, MCP handlers,
  `setup.sh`, and the enforcement code itself (`build_adapters.py`,
  `validate.py`, `core/scripts/tests/`). Rows the reports flagged sensitive
  carry `heightened-review` and are flagged again in the pull request for
  explicit owner eyes.
- **Every marked row landed with an adjustment; none was downgraded** (KTD1).
  Where the upstream read forced a different shape, the Rationale says what
  changed and why; where it did not, the row says "as proposed".
- **Row contract (machine-parsed):** candidate rows match
  `| RW-2026-09-12-N |`; verdict ∈ {adopt, adapt, document}; `Adopted-in`
  holds the implementing commit once the close-out commit exists (`—` until
  then, per R32). An `Adopted-in` link that does not resolve in git is
  flagged by the validator's `ledger-link` warn class.
