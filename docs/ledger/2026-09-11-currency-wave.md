## Method and trust boundary

- **Fetch-only profile:** unchanged from July — HTTPS reads only
  (`commits.atom`, the compare API, and raw `VERSION`/`CHANGELOG.md` reads
  for the repo watcher; the raw CHANGELOG and five doc pages for the
  platform watcher); no clone, no local checkout, no execution of anything
  fetched; per-fetch size caps (compare payloads over the ceiling were
  reduced to titles, dates, and paths; the two oversized upstream
  CHANGELOGs were read for their top headers only). REST budget 6/6 for
  the repo run; no `.diff` or atom-title fallbacks were needed.
- **Classification (report-only):** each watcher classified by title plus
  changed-file path — the platform watcher across four fresh subagents (one
  per ~10-version slice) with the parent verifying every adopt-candidate
  against the live repo; the repo watcher across six per-repo subagents
  cross-checked against the adoption matrix so already-adopted or
  already-deferred patterns were not re-proposed. Report-row verdicts are
  title-and-path signal, not line-by-line diffs; both reports say so in
  their Gaps.
- **Upstream patches read before implementing:** for every implemented row
  the real upstream patch (or the release note, where the diff itself lay
  beyond the fetch cutoff — RW-2026-09-11-19, RW-2026-09-11-34) was fetched
  into the session scratchpad and summarized as untrusted evidence; each
  sensitive row's `implemented-from:` tag names the sha7 its implementation
  was re-derived from. No code was copied — every mechanism was
  re-implemented in this repo's conventions, and instruction-shaped text
  found in a report, a patch, or a fetched page was treated as data.
- **Defang-on-write:** as July — every verbatim upstream string passed
  through `core/scripts/defang.py` in the reports before landing here and is
  copied unchanged (`hxxp` stays `hxxp`); quotes are clearly marked;
  everything else is authored prose.
- **Authoring guideline:** as July — respectful, fit-to-this-repo technical
  assessments written as if the named maintainer will read them. A skip,
  adapt, document, or defer verdict states why a pattern does not fit
  *here* (or not *yet*) — never a quality judgment of the source. "Import
  nothing" remains a valid outcome.
- **Sensitive surfaces:** the July list stands — hooks, `settings*`,
  allowed-tools, `.gitignore`, guard/safety code, MCP handlers, `setup.sh`,
  and the enforcement code itself (`build_adapters.py`, `validate.py`,
  `core/scripts/tests/`). Rows the reports flagged sensitive carry
  `heightened-review`; every implemented one names its upstream patch
  (`implemented-from: <sha7>`) and every downgraded one carries its reason
  on the row (R28). Enforcement-code rows the reports did not flag still
  cite their upstream sha7 in the rationale.
- **Row contract (machine-parsed):** candidate rows match
  `| CLI-YYYY-MM-DD-N |` or `| RW-YYYY-MM-DD-N |`; verdict ∈ {adopt,
  adopt-partial, adapt, document, defer, skip}; `Adopted-in` holds the
  implementing commit once the wave's commit exists (`—` until then, filled
  in a follow-up commit per KTD9). An `Adopted-in` link that does not
  resolve in git is flagged by the validator (`ledger-link`).
