# Spec anti-patterns — avoid when drafting, flag when found

The `/spec` skill checks these after saving and prints violations. Violations do **not** block the save — they print as soft flags so you decide whether to fix.

1. **Expanded PRD (HARD rule)** — any sentence that re-explains WHAT or WHY a feature exists rather than HOW it is built. Test every line: if it would be equally true sitting in `prd.md`, cut it and cite `prd.md §N`. More than 20% of spec lines restating PRD what/why = **Major gap**. The §2 Build Delta table is where PRD needs get *linked*, never copied.
2. **Placeholders shipped** — any `TBD`, `TK`, `…`, or "to be determined" in the final doc. Either infer with `[INFERRED — low confidence, rerun with --ask]` or consciously defer with a named trigger (`deferred until M1 metrics — see §16`).
3. **Tech choice without justification** — a named library / framework / service with no "why this over what" note. Every P0 stack choice in §5 must cite at least one rejected alternative and a one-line reason.
4. **Missing rejected alternatives** — §23 MADR contains fewer than 3 rejected options, or the spec lists only what was picked. Any non-trivial architectural decision deserves a `Rejected: X because Y` line.
5. **Silent integration points** — references external services (`manager-ai`, `Granola`, `Slack`, `Perplexity`, `OpenAI`) without naming the tool / endpoint / auth mode / rate limit / failure behavior. Every external dependency gets a one-row contract in §13, and integrations without rate limits hide the architecture (cron intervals, fan-out). Fix: fill the §13 row including rate limits.
6. **Over-specifies to line-of-code level** — pseudo-code blocks longer than 15 lines, exhaustive variable-level type declarations, or implementations that belong in code review. Spec shapes, doesn't implement.
7. **No assumptions ledger** — §4 Assumptions is missing, empty, or all assumptions silently baked in. Each P0 assumption gets a row: what it is, source, risk if wrong, how we'd validate.
8. **Scope creep into adjacent skills** — no product-requirement restatement (that's PRD), no risk matrix (pre-mortem), no business model (lean-canvas), no GTM timeline (gtm-plan). Link and summarize in one line max.
9. **Empty Non-Goals** — §3 re-lists the PRD's product goals instead of fencing engineering scope. Fix: replace with engineering-framed Non-Goals / explicit Out-of-Scope the PRD does not state (the build exclusions that prevent scope creep). Goals live in the PRD; this section's value is the out-of-scope fence.
10. **Endpoints in prose, not payloads** — §11 describes an interface in sentences instead of concrete request/response shapes (JSON blocks, type signatures, CLI/queue message shapes). Payload shapes ARE the contract — show them.
11. **Happy-path-only error handling** — §12 omits sad paths, or skips EARS form (`IF <trigger> THEN the system shall <response>`). Fix: cover at least bad input, external failure, auth failure, and the riskiest pre-mortem failure — each as an EARS row. Unhandled sad paths are where AI builders silently skip work.
12. **Decorative testing** — a §19 Testing section that names lanes but enumerates zero tests, or any P0 FR lacking a pre-named failing test ordered before its implementation in §20. "Tests later" = no tests.
13. **No build-order slice** — §25 Milestones describe end-state architecture without a walking-skeleton first milestone, or §20 WBS is missing / has fewer than 12 tasks at active stage. Without a slice, `/sprint-plan` and `/user-stories` have nothing to pull from.
14. **AI behavior contract covering only Good cases** — the spec names an LLM surface (Claude / GPT / Anthropic / OpenAI / any model call) but §18.A is absent or ships without the 5 Good / 5 Bad / 6 Reject rows (the Reject categories: PII echo, jailbreak, policy violation, competitor mention, attribution-claim, locale mismatch) plus a cost+latency budget. The value is in Bad + Reject. Fill §18.A or render `N/A — no model-call surface in MVP` with justification.
15. **Generic toolchain dump** — any §21/§22 tool row not traceable to a named §7 component, a §20 task, or an FR is boilerplate. A row copyable verbatim into another project is too generic — cut it or tie it to a concrete component/task.
16. **Unpinned / unverifiable stack** — a stack named in prose without a pinned, registry-verifiable §5 manifest excerpt AND a ≥6-path §6 file tree. "We'll use Next and some chart lib" is not a build contract. Fix: emit the pinned manifest block + the real file tree the tasks reference.
17. **No executable acceptance** — a §25 milestone (or any build section) without an executable Acceptance check/command and a pass signal. "Looks done" is not a pass signal. Fix: add the literal command an agent runs to prove the slice works.
18. **Unreviewed generated code** — AI- or marketplace-generated code recommended in §21/§22 without a paired §19 generated-code-review + SAST lane and a §18 package-existence control. AI code hallucinates ~20% of imports (slopsquatting) and ships a ~45%-vulnerable surface; it is not exempt from review. Fix: add the §19 Generated-code review lane + the §18 verify-on-registry-before-merge control.
